## P11: IFC â†’ analytics pipeline

**Location:** `projects/p11-ifc-analytics/`
**Criteria:** E2, E4, E6, D5, D6
**Stack:** IfcOpenShell (Python; verify current API for the pinned version), pandas, DuckDB, Parquet, Typer, pytest.
**Goal:** extract spaces, elements, types, systems, properties and quantities from IFC into analytical tables, check model data quality, and reconcile the model against the space register.

### Inputs
1. A public sample IFC (buildingSMART Sample-Test-Files or IfcOpenShell test files; record licence in `DATA.md`; download via script, do not commit if the licence is unclear).
2. A **synthetic IFC** generated by `make_sample_ifc.py` using the IfcOpenShell API: project â†’ site â†’ building (aligned to campus building B003) â†’ storeys â†’ `IfcSpace` with `Qto_SpaceBaseQuantities` â†’ distribution elements (AHUs, boilers, pumps, fan coils) with classification references, manufacturer/type property sets and system membership. Include deliberate defects: elements without type, without classification, without space containment, duplicate names, zero-area spaces, 12 rooms whose area differs > 10% from the register, 5 rooms missing from the model (match `ground_truth.yaml`).

### Outputs (Parquet, plus DuckDB views)
`ifc_project, ifc_storeys, ifc_spaces, ifc_elements, ifc_types, ifc_systems, ifc_system_members, ifc_properties_long (global_id, pset, property, value, unit), ifc_quantities_long, ifc_classifications`.

### Features
- Handle IFC2X3 and IFC4 (document differences encountered).
- Area from `Qto` where present, documented fallback otherwise (flag the source of each area value).
- Stable key = IFC GlobalId; crosswalk to `space_id`/`asset_id` via `entity_crosswalk` (see P18).
- **Model QA report** (HTML + CSV): counts by class; elements missing classification / type / space / required property sets; duplicate GlobalIds; zero or negative areas; spaces without storey; naming-convention conformance; completeness % per property set.
- **Reconciliation:** `recon_model_vs_register` (area delta per room, rooms in model not in register and vice versa, summary by building). Feeds the P03 cross-source checks.
- CLI: `ifc2tables model.ifc --out data/gold/ifc/`; incremental by file hash; log runtime vs element count.
- Power BI handoff: "Model data health" page and "Space & asset explorer" page (spec only).

### Acceptance
- All seeded model defects appear in the QA report (counts match the generator's log).
- All planted area mismatches and missing rooms found by reconciliation (100% recall).
- No geometry processing required (state this; extraction stays fast), runtime table documented.
- Works on both the public sample and the synthetic model; tests use a tiny fixture IFC committed to the repo.

**CV bullet:** *Built a pipeline that converts IFC models into queryable analytical tables with automated data-health reporting and model-vs-register reconciliation (100% of seeded discrepancies found).*
