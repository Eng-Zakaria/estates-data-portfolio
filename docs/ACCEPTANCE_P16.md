## 1. Pipeline delivered

| Stage | Module | What it does |
|---|---|---|
| Fetch (BDG2) | `data_bdg2.py` | Zenodo DOI `10.5281/zenodo.3887306`, 595,266,464-byte zip, md5-verified, cached; subset selection reads metadata + electricity header (never hard-codes buildings) |
| Load (campus) | `data_campus.py` | half-hourly truth readings + hourly weather, merged with meter metadata |
| Cleaning | `cleaning.py` | null/negative/zero counts, flat-line windows, winsorising for baseline fitting only |
| Baselines | `baselines.py` | (a) median profile by dow/hour, (b) Ridge on hour-of-week + heating degree-hours, (c) `HistGradientBoostingRegressor`; rolling-origin CV with CVRMSE/NMBE |
| Detectors | `detectors.py` | MAD z-score, Isolation Forest, two-sided CUSUM, mean-shift change-point scan, overnight baseload ratio, overnight-drift test |
| Typology | `typology.py` | 7 fault labels; savings in kWh / £ / kgCO₂e with ±25% band |
| Evaluation | `evaluate.py` | 210 labelled injections, per-method/per-type P/R/F1/delay |
| Reports | `report.py` | dependency-free inline-SVG evidence plots, HTML pages, parquet outputs |
| CLI | `cli.py` | `fetch-bdg2`, `run-campus`, `evaluate`, `review-bdg2` |

Outputs: `outputs/anomalies.parquet` (18 meters), `outputs/building_scorecard.parquet`,
`outputs/action_list.json`, `outputs/metrics.json`, 11 per-building HTML evidence

## 6. Bugs found and fixed during verification (not hidden)

1. **CUSUM muted its own signal.** A global median/MAD reference let a sustained
   shift drag the reference toward itself; the unit test for a pure +8σ step
   failed against the original code. Fixed by taking the reference from the
   leading 25% of the series. Documented in `docs/methodology.md` §3.
2. **NaN weather crashed the Ridge/GBM fit** on BDG2 meters
   (`Input X contains NaN`). `baselines.design_matrix` now documents that
   missing heating degree-hours are filled with 0.0 ("mild day"), and
   `pipeline` fits only on rows with a finite reading.
3. **NaN targets crashed the fit** when a meter's 28-day training window was
   entirely missing. `pipeline` now falls back to any finite period; if a meter
   has no finite reading at all it returns a data-quality-only result
   (`missing_data`, £0) instead of crashing. All four cases are pinned in
   `tests/test_gaps.py`.
4. **`np.quantile` on an all-NaN array** raised `IndexError` from
   `winsorise_fit`. It now returns the input unchanged rather than inventing a
   bound.
5. **Drift false positives.** A residual first-vs-last test flagged every meter
   for drift because the baseline develops seasonal bias over 24 months. Replaced
   with an overnight-mean creep test (nights are occupancy-free).
6. **The overnight-baseload threshold does not transfer between profiles** —
   the most important finding of the verification pass. `docs/methodology.md`
   claimed a measured gap (normals ≤ 0.47, planted ≥ 0.55) that held on the small
   profile. Running the same measurement on the **default** profile
   (`scripts/threshold_separation.py`) shows normal electricity baseloads up to
   **0.550** of peak, giving **21 false positives out of 58** normal electricity
   meters, while the planted fault measures only **0.530** because the generator
   applies it 9 months into the series. The claim in the methodology doc has been
   corrected, the measurement script committed, the failure written up in
   `docs/methodology.md` §3.1, flagged at the top of `README.md` §5 and in
   `docs/OPEN_QUESTIONS.md`, and `make p16-thresholds` added so the check is
   runnable rather than a one-off. The overnight-drift threshold was measured at
   the same time: 0 false positives on both profiles.

## 7. Known gaps (stated, not worked around)

- **Overnight threshold fails on the default profile** (§6 item 6). Not fixed
  here because the correct fix (per-meter or per-building-type baseload
  comparison) needs an estate baseline the synthetic profiles do not provide, and
  tuning it against the evaluation data would invalidate the injection study.
  Recorded in `docs/OPEN_QUESTIONS.md`.
- **Project tests are not in CI.** The root `ci.yml` gate runs
  `packages/campus_synth` and `platform` tests only (root `pyproject.toml`
  `testpaths`), so P16's 36 tests run via `make p16-test` / `make p16-run` and in
  local verification, not in the GitHub Actions gate. This is a repo-wide gap
  shared with the other project folders; widening `testpaths` or adding a matrix
  job is a P05 change that needs its own acceptance refresh.
- **`threshold_separation.py` is not yet wired into `make eval`** — it is a
  separate `make p16-thresholds` / `make p16-run` step so the 2-minute eval
  stays 2 minutes.

## 8. Deviations from spec

- **No `ruptures`**: change points come from CUSUM + a sliding mean-shift scan,
  both unit-tested on series with known answers.
- **No plotly/matplotlib**: evidence plots are dependency-free inline SVG
  (down-sampled to ≤ 500 points), so the HTML pages render anywhere.
- **No `.pbix` produced**: Power BI Desktop cannot be driven headlessly; the
  full handoff is provided instead (`powerbi/`), per the AGENTS.md protocol.
